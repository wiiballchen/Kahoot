# 派對快問快答（Kahoot 類型多人即時問答）

這是一套可自行部署的多人即時問答網站，採用 Node.js + Express + Socket.IO。專案預設包含 8 題（第 1 題暖身、其餘 7 題正式題），每題 4 個選項、10 秒作答，並在每題結束後顯示更新後的前 10 名。

## 功能

- 賓客使用手機掃描 QR Code，或開啟網址並輸入 6 位數 PIN 加入。
- 每位玩家自行設定暱稱；同一場遊戲內暱稱不可重複。
- 1 題暖身題 + 7 題正式題，總計 8 題。
- 每題 10 秒；伺服器端計時，避免玩家手機時間不同步。
- 答錯或未作答得 0 分；答對依作答速度獲得 500–1,000 分。
  - 剛開始就答對：接近 1,000 分。
  - 接近 10 秒才答對：接近 500 分。
- 暖身題也計入總分，並在暖身題結束後顯示排行榜。
- 每題結算後展示動畫排行榜；最後一題結束後顯示最終前 10 名。
- 主持人可在網頁後台編輯題目、四個選項、正確答案與答案說明。
- 遊戲中的答案不會提前傳到玩家瀏覽器，題目結算時才公布。

## 本機啟動（Windows）

1. 安裝 Node.js 20 或更新版本：<https://nodejs.org/>。
2. 解壓縮專案資料夾。
3. 第一次啟動時，雙擊 `start-windows.bat`。它會建立 `.env` 並安裝套件。
4. 開啟 `.env`，把 `HOST_PASSWORD` 改成自己的主持人密碼。
5. 再次雙擊 `start-windows.bat`，看到服務啟動訊息後，開啟 <http://localhost:3000/host>。
6. 主持人登入密碼就是 `.env` 裡的 `HOST_PASSWORD`。

也可以在專案目錄開啟終端機執行：

```bash
npm install
npm start
```

玩家入口：`http://localhost:3000/`  
主持人後台：`http://localhost:3000/host`

## 放到網路上（Render）

建議使用 Render 的 Node.js Web Service。專案已附 `render.yaml`，設定了 Node 執行環境、啟動指令、健康檢查和 1 GB Persistent Disk。

1. 建立 GitHub 帳號，新增一個 repository。
2. 將本專案所有檔案上傳到 repository（不要上傳 `node_modules`、`.env` 或 `data/store.json`）。
3. 註冊 Render，連結 GitHub。
4. 在 Render 選擇 **New → Blueprint**，選取剛才的 repository，讓 Render 讀取 `render.yaml`。
5. Render 要求設定 `HOST_PASSWORD` 時，輸入一組只有主持人知道的密碼。
6. 建立完成後，Render 會提供 `https://你的服務名稱.onrender.com` 網址。
7. 主持人開啟 `https://你的服務名稱.onrender.com/host`；賓客開啟主網址或掃描主持台上的 QR Code。

`render.yaml` 使用 Starter Web Service，並掛載 1 GB Persistent Disk。Render 官方目前列出的低階付費 Web Service 為 US$7/月，Persistent Disk 為 US$0.25/GB/月；依此 Blueprint 的基本服務與 1 GB 磁碟估算約 US$7.25/月，另可能有稅金或超額用量。價格以 Render 帳單頁面為準。

不建議正式活動使用 Render 免費 Web Service：免費服務閒置 15 分鐘會休眠，喚醒可能需要約 1 分鐘；而且免費服務沒有可掛載的 Persistent Disk。活動當天建議使用付費服務，並在活動前先實際測試整場流程。

## 如何主持一場遊戲

1. 開啟 `/host`，輸入 `HOST_PASSWORD` 登入。
2. 在「題目與答案設定」編輯 8 題。第 1 題是暖身題，第 2–8 題是正式題。
3. 每題填題目、4 個選項，並點選正確答案左側的圓鈕；答案說明可留空。
4. 按「儲存全部題目」。遊戲進行中不能修改題目，請在建立房間前完成設定。
5. 按「建立新遊戲房間」。主持台會顯示 6 位數 PIN、加入網址與 QR Code。
6. 賓客掃描 QR Code，或進入主網址輸入 PIN 和自己的暱稱。
7. 確認參賽人數後，主持人按「開始暖身題」。
8. 每題開始後，玩家有 10 秒作答。時間到會自動結算並展示前 10 名；排行榜展示約 6.5 秒後，主持人即可開始下一題。
9. 第 8 題結算後，系統顯示最終前 10 名。

## 題目如何設定

主持人後台提供題目編輯器，不需要修改程式碼：

- 題目：最多 180 字。
- 選項：固定 4 個，每個最多 70 字。
- 正確答案：點選該選項左側的圓形按鈕。
- 答案說明：選填，會在結算時顯示。

目前題庫的預設題目是示範用，活動前請改成自己的題目並儲存。

## 分數如何計算與保存

分數由伺服器計算，玩家端不能自行修改：

- 答錯、未作答：0 分。
- 答對：依答題耗時給 500–1,000 分，越快越高。
- 計分公式：`round(1000 - 作答耗時毫秒 / 10000 × 500)`，並限制最低 500 分。

即時遊戲狀態和分數由 Node.js 伺服器管理。每次加入玩家、送出答案或題目結算時，伺服器會將目前場次、玩家分數、作答紀錄與題目設定寫入 `DATA_DIR/store.json`，採用暫存檔再改名的方式保存，降低寫入中斷造成的風險。Render 部署時 `DATA_DIR=/var/data`，因此資料寫入 Persistent Disk；本機則寫入專案的 `data/store.json`。

伺服器重新啟動時會嘗試還原尚未結束的房間和倒數時間。每場結束後，系統會將全體玩家的最終排名存入歷史紀錄，最多保留最近 50 場；比賽畫面只展示前 10 名。

## 架構說明

- **前端**：HTML、CSS、JavaScript，玩家使用手機瀏覽器即可參賽，不需安裝 App。
- **後端**：Node.js + Express，負責網頁、主持人 API、房間與遊戲規則。
- **即時通訊**：Socket.IO，將題目開始、玩家作答、倒數結束、排行榜更新即時推送給所有連線者。
- **計時與計分**：以伺服器時間為準，避免玩家自行調整手機時間影響結果。
- **資料保存**：JSON 檔案 + Render Persistent Disk。這個版本採單一伺服器實例，適合一般聚會、尾牙或小型活動；若預期數百至上千人同時參加，應再改成共享資料庫與多實例架構。

## 安全與使用提醒

- 部署時一定要設定自己的 `HOST_PASSWORD`，不要沿用範例密碼。
- 不要把 `.env`、`store.json` 或主持人密碼上傳到公開 GitHub repository。
- 目前設計為同一時間一個遊戲房間，最多 200 位玩家；主持人結束一場後才能建立下一場。
- Render 掛載 Persistent Disk 的服務為單一實例設計，不要在未調整架構前任意開啟多實例。
